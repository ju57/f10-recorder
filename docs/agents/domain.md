# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root.
- `docs/adr/` for architectural decision records.

Before exploring domain concepts, read the glossary if it exists.
Read ADRs relevant to the area being changed.

If these documents are absent, proceed silently. Create them through
domain-modeling work when terminology or decisions are resolved.

Use glossary terms consistently in issues, proposals, hypotheses and tests.
If a needed concept is missing, check existing project language and note
any real terminology gap for domain modeling.

If a proposal contradicts an ADR, identify that ADR and explain why its
decision should be reconsidered.
