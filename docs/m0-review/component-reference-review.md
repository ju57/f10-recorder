Prioritize these details for the next wireframe review:

1. **#02:** retained device identity, full-name access and distinct disconnected/denied states. For example, `USB microphone · Disconnected` in the selector, with no duplicate missing label beside the icon. A never-configured input can retain the accepted No microphone available wording. Permission restoration still requires explicit enabling; same-device reconnection preserves enabled/muted intent. No silent substitution.
2. **#09:** concise, actionable blocking errors for source/folder/storage. Preserve the current draft and put focus on the first affected field. Add permission recovery as a nonblocking audio state, not as a Finish gate.
3. **#10:** failed-start and busy visuals specified by Q91. Keep the single primary action and the absent divider. The source does not itself demonstrate failure or retry; that transition is an F10 proposal grounded in the accepted contract.
4. **#06, optional:** one visual boundary for folder text/action focus. The current placement already works; this is a small interaction refinement, not a new picker layout.

Keep #01, #05 and #08. Defer #03 filtering, #04 peak dynamics and #07 alternate track choice until there is a concrete usability need. No changes are recommended to the source-scope sentence, estimate placement, default selections or form layout.

For the HTML board, any selected detail becomes a clearly simulated scenario using the existing draft state. Descriptive popup rows would need a custom review control; native HTML select options do not reliably support two-line templates. Keep invalid input text separate from its last committed value, existing error associations and all accepted nonblocking audio semantics.

For future native implementation, the current Avalonia project already uses `ComboBox`, `NumericUpDown`, `TextBox`, `CheckBox` and `Button`. Candidate adaptations are device item/selected-value templates, a linked `Slider` and numeric control, a lightweight drawn meter, an inset folder command and one async start command. These are mappings for later implementation, not verified native components. No React dependency or web migration is proposed. Native focus, device identity, permission, picker, scaling and worker integration need their own validation.
