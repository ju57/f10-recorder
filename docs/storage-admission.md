## Private five-minute receipt

A private build may embed a one-use issuer's RSA public key through
`F10PrivateReceiptPublicKey`. The account-private catalog can then read
`reference-private-5m-v1.json` for the five-minute profile. Default builds
contain no issuer key. The signed payload binds the consuming exporter, the
original measured exporter, the parent calibration, the pre-run contract,
both output observations and the digest of the independently reviewed evidence.
Keep the issuer, key material, observations and machine-specific receipts
outside the repository.

The loader verifies the signature, original training model, capture profile,
current host and unchanged storage limits. It derives the consuming profile's
scope from the signed arguments and rechecks the protected receipt and actual
destination when deciding applicability. Removing or changing the receipt
withdraws the cached model. Five-minute direct and private receipts cannot share
a five-minute catalog, and a shared coverage receipt conflicts with the private
receipt. Other durations need their own applicable evidence.

This exception accepts measurements through verified closure of the recording
and both saves. Independent review must bind subsequent experiment-only report
writes and preserve the original controller outcome. Storage admission still
uses the ordinary reservation, capacity and producer-closure checks.

## Current issue 83 capacity-policy candidate

Periodic capacity samples use caller-visible free bytes on each actual target
volume minus **full outstanding commitments**. They take no credit for an
allocated prefix, alias, departed process or guessed cleanup. Admission and
materialization retain comprehensive native identity/allocation validation;
producer absence and observer closure remain separate release requirements.
The account ledger uses version 3 with a new epoch for every actual mutation.
A capacity query releases the ledger lock before native free-space I/O, then
rechecks the exact epoch; an intervening change supplies no fresh evidence.
Legacy ledgers transition without recovering owners or reducing claims.

Capture and accepted exports each own at most one pending capacity query.
The candidate samples at 200 ms and permits a bounded monitoring delay only
within explicit **2,000 ms growth coverage** and conservative remaining cover.
Query start and actual successful completion are retained; callbacks, busy
results and forced checks cannot renew the successful evidence epoch. Old
500 ms growth receipts are ineligible. Matching new receipts must measure
positive capture growth across the entire 2,000 ms horizon plus actual stop
growth; this is a finite qualified envelope, not a universal disk guarantee.
Continued unavailable monitoring or insufficient cover requests controlled stop
and retains uncertain claims. A stop request is distinct from producer absence
and observer closure. Blocked capacity/guard reads do not hold the stop lock.

New acquisition still warns below five decimal GB and stops before the two
decimal GB floor after commitments and its measured growth/stop allowance.
Already accepted exports may continue below that acquisition floor only while
their outstanding commitments remain covered. Write, flush, close, validation
and checked publication failures still fail unpublished outputs truthfully.
Publication remains the save-success point; later temporary cleanup problems
remain diagnostics. File identity, source precision and sticky integrity checks
are independent of the capacity-delay allowance.

Save timing includes capacity query count, completions, pending state and total
and maximum query work, including queued time, policy checking and native I/O.
That work overlaps capture/export stages; it must not be added again to those
elapsed stage durations. Worker CPU/RAM/I/O measurements still include it.

Coalescible global budget work uses its own 100 ms completion cadence, separately
from the genuine capacity-evidence timestamp. A lagging query epoch cannot
trigger a full inventory on every callback. Coalescing does not renew that epoch:
expiry still includes all checking work and rejects after the same 2,000 ms
coverage. Dirty and forced boundaries still run immediately; busy work remains
dirty and supplies no renewal. Work coalescing stops within the final 100 ms of genuine evidence cover, allowing
the observer to consume an available completed query before the old epoch expires.
`ObservationAttempts` counts actual full-work
calls separately from genuine evidence updates in `Observations`. Native local
output checks still run on each callback. Changed binaries need fresh
qualification and ordinary-worker measurements before any performance claim.

Qualification's broad inventory measures allocation, growth and coverage. Its
latency is not a separate product heartbeat. Lightweight capacity monitoring
also charges the complete finite cohort without inventory-derived free-space
credit. Missing inventory evidence outside the declared growth horizon leaves
qualification inconclusive. Acceptance requires focused I/O/export controls,
applicable exact-build qualification, real capture draining and ordinary-worker
Saved measurements. Local receipts apply only to their bound build and profile;
they do not establish later-build or final performance acceptance. Older 500 ms evidence below documents
the previous contract and cannot qualify this candidate.
