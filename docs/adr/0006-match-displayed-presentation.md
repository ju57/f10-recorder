# Match the displayed presentation in recorded video

For the beta, recorded video must match the source's displayed presentation, including intentional stretching and visible aspect-ratio borders, rather than always preserving the raw render surface's proportions. This prioritizes the user's actual view: a 1280x960 game stretched across a 1920x1080 display must be recordable with the same stretched 1920x1080 appearance, even when reproducing the presentation requires enlarging or transforming a smaller captured surface. Capture paths must qualify any GPU/display scaling transform without changing the user's display/NVIDIA preferences or broadening selected-window capture to desktop content; this records the accepted design, not current runtime qualification.

Q157, accepted on 24 October 2026, fixes output dimensions for each recording/replay session, resolving Native to the displayed size when that session starts. Fit later source resizing inside that frame without cropping or introducing new stretching; if the source's actual displayed aspect ratio changes, padding is permitted as a narrow exception to the no-added-borders rule, preserving continuity. A raw 4:3 render stretched to a displayed 16:9 presentation still records stretched 16:9; a raw render-size change alone does not justify new padding. A new session resolves its output dimensions again. Presentation detection, encoder-safe dimensions, rotation and native qualification remain engineering work.
